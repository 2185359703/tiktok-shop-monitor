# 服装监测报告

报告将已采集的美国站公开观察转为店铺覆盖、价格区间、规格缺货和变化证据，帮助选择下一批需要跟踪的商品。支持可离线查看的 HTML、Markdown 摘要和完整 JSON，不需要访问 TikTok 或启动采集。

## 导出和查看

项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.export_report
```

命令只读取现有 MySQL，默认回看 24 小时事件；不创建任务，不调用网站，不修改当前商品、SKU 或快照。终端返回三个绝对文件路径和统计摘要。默认目录为 `data/exports/reports/`，可在 `[report].report_directory` 配置。

指定观察截止时间或更长的事件窗口：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.export_report --as-of '2026-10-14T18:00:00+08:00' --lookback-hours 24
```

截止时间必须带时区、不能在未来；回看窗口为 1–720 小时。所有文件以 `us-clothing-日期-JSON摘要前16位` 命名，保留历史导出，不覆盖旧文件。同一份完整输入重复导出会复用原文件。不同生成时间通常产生不同摘要。

HTML 内嵌全部商品数据、样式与脚本，没有远程字体、图片或脚本依赖。支持标题/商品 ID/店铺搜索、店铺筛选、历史详情筛选和每页 20 个商品。手机表格可在自身容器横向滚动。打印按钮打印当前筛选和当前页；完整清单在 JSON 和可分页的 HTML 中。

## API 与队列任务

运行 `scripts.run_api` 后：

| 入口 | 行为 |
| --- | --- |
| `GET /api/v1/reports/current?format=json` | 读取当前数据库观察，返回完整报告 |
| `GET /api/v1/reports/current?format=html` | 返回可筛选的报告页面 |
| `GET /api/v1/reports/current?format=md` | 返回 Markdown 摘要 |
| `POST /api/v1/reports/jobs` | 创建持久化报告任务，返回 task_id、created 和 status |
| `GET /api/v1/reports/jobs/{task_id}/files/{format}` | 下载已完成任务的 json/html/md 产物 |

GET /current 不落盘、不创建任务；可以增加 `lookback_hours=48`。同一 App 对同市场、价格上下文、币种和回看时长的并发请求只构建一次，成功编码后缓存 60 秒，命中时保留原始 `as_of`、`generated_at`；不把旧报告改时间冒充实时数据。缓存仅保留一个上下文的 JSON、HTML、Markdown 字节，不持有数据库会话。构建失败返回明确错误，之后的请求可以重试。

JSON 中 ID 与金额保留字符串。报告每 250 个商品分页读取，只投影历史快照所需字段，并在数据库中汇总 SKU 状态，不一次性加载全部 SKU 对象或完整快照 JSON。安全上限为 100,000 个商品，超限明确拒绝，不截断冒充全量；这个上限不是已验证的容量。事件详情最多返回 1,000 条，另保留完整事件计数及 `events_truncated` 标识。HTML 的关注区域显示前 5 条事件，完整事件详情看 JSON。

创建报告任务需要现有写接口 Token，并显式启用 `report_generation`。请求体示例：

```json
{"lookback_hours":24,"scheduled_for":"2026-10-14T10:00:00+00:00"}
```

不传 scheduled_for 时按当前 UTC 小时生成任务。同市场、价格上下文、币种、报告类型、窗口和回看时长重复提交返回同一任务，不重开已完成任务。Worker 校验任务币种和上下文与运行配置一致后执行。

scheduled_for 只用于任务去重；实际 report_as_of 是执行时的数据库时间，不能把延迟执行的任务伪装成过去窗口的实时观察。报告在 Worker 的 prepare 阶段使用显式会话工厂和同一事务视图构建，关闭只读事务后导出；主线程继续处理 MQ 心跳和 SQL 租约续期。apply 仅在租约栅栏下核验资源并登记产物检查点，SQL 提交后才 ACK。缺少会话工厂明确失败，不回退读取隐式数据库配置。

只执行一个报告任务的有限实跑命令：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.run_report_job
```

需要配置项目 MySQL、RabbitMQ 和 Redis。脚本仅启用报告、使用自己的队列范围，不领取已有网站任务；不会修改项目长期运行开关。同一 UTC 小时重复执行会复用已完成产物。正常 Scheduler/Worker 也能执行已创建报告任务，但当前没有自动生成日报的定时器。

## 读数口径

- 只统计 `tiktok_shop / US / USD / public_listed` 的可比较观察，不混入登录优惠或其他市场。店铺来源分组不是商家主营类目。
- 按实际 captured_at 选择截止时间前最后一次有效商品快照，再只统计这次快照中真实观察到的 SKU。不会把当前表中保留的旧 SKU 拼入历史观察。
- 没有快照的商品仅在当前 last_seen_at 不晚于截止时间时使用当前字段；无法重建过去观察时保留身份、将观察字段留未知。
- SKU 缺货率分母为 in_stock + out_of_stock，unknown 和 partial 不当作确定库存。没有已知分母时为 NULL，页面显示横线。
- 起价分布每个商品只计一个价格下限，区间左闭右开，100 USD 及以上进入最后一档；不使用 SKU 数量给多规格商品额外权重。
- 事件按后快照实际观察时间归入窗口，保留检测时间、前后值及前后快照 ID；数量为公开可售数量，不代表核验了仓库库存。
- 原始公开类目未提供时归入 unknown；不从标题或种子来源猜测商品类目。累计销量不用于日销量、GMV 或全市场排名。

商家文本通过 textContent 插入页面；内嵌 JSON 转义 HTML 边界，Markdown 转义表格分隔符。商品外链仅允许已核实的公开 PDP 路径。下载只查已完成的本市场报告任务，文件必须位于配置导出目录。

文件系统和 MySQL 没有跨介质原子事务。SQL 提交失败时可能留下未关联导出文件；任务不会因此被标为成功，下载入口只认成功任务检查点。文件不能由当前商品表重新猜测出历史报告。
