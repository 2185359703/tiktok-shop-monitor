# 服装店铺种子链接核验

日期：2026-10-13；市场：美国站。先核验原始 100 个店名；用户明确允许后，为其中未核实链接的 22 条补选同类店铺。不登录、不下单、不绕过安全验证。

## 可直接使用的结果

- 主名单：`data/seed/shops_us_clothing.csv`，100 条已核验链接，对应 100 个不同真实店铺 ID。
- 采集入口：`data/seed/shops_us_clothing_verified.csv`，100 条，与当前主名单一致。
- 当前待确认：`data/seed/shops_us_clothing_pending.csv`，0 条，仅保留表头。
- 原始归档：`data/seed/archive/shops_us_clothing_names_20260925.csv`，100 条最初名称观察，来源类目和日期均保留。
- 被替换原名：`data/seed/archive/shops_us_clothing_replaced_names_20261013.csv`，22 条原记录。
- 替换对照：`data/seed/shop_replacements_20261013.json`，逐条保留原名、新店名、真实 ID、链接和核验证据。

原已核验的 78 个店铺保持原 seed_value。22 条替换记录使用新店铺的真实页面名称，按原监测分组补齐数量。shop_url 与 source_url 使用实际访问的店铺页面，observed_at 为核验日期。没有从店名生成地址后直接当作真实链接。

监测分组数量保持不变：women_clothing 25、women_dresses 21、men_clothing 21、activewear 17、sportswear 12、lingerie 4。分组用于选入监测池，不声称商家只经营一个服装类目。

## 核验过程与证据

1. 逐个检索 100 个店名的公开店铺页面，搜索结果仅作为候选，不直接认定为有效入口。
2. 实际访问候选店铺页面，读取公开 SSR 业务字段，核对 URL 中的店铺 ID 与页面 seller_id 一致。
3. 已有确认 ID 的记录必须匹配该 ID；没有 ID 的记录要求页面店名明确匹配，不把同品牌的相似店铺混在一起。
4. 对搜索未直接列出入口的名称，检查部分公开商品页的 shop_info/shop_link，从真实卖家信息获得店铺入口，再独立访问店铺页面核验。
5. 部分商品页返回 200，但标题为 Security Check，并非商品数据；识别后停止这批来源访问，没有破解验证码、修改指纹或重放签名接口。

最终 100 个店铺入口均有实际 HTTP 页面与身份核验，不仅是搜索结果命中。78 个来自原名单，22 个来自用户批准的补选；补选也独立访问并核对 ID，未把同一店铺的不同链接重复计数。证据 JSON 为白名单投影，只保存公开 ID、名称、链接、时间、响应摘要与业务字段路径，不保存完整 HTML、Cookie、签名或会话凭据。

`data/samples/seed-links/verification.json` 记录每条结果的 original_row_hash、真实店铺 ID、核验方式、核验时间和 evidence_path。店铺页面证据在 `data/samples/seed-links/pages/`；通过商品页发现入口的证据在 `product-sources/`。

本次所获链接可以继续用于少量商品列表验证，但不保证平台今后的页面结构、可访问性或店铺名称不变。

## 数据库同步

通过经核验的具体店铺入口确认原始记录，保留原始 100 条 seed_shop_observations、raw_record 和 row_hash。22 个补选店铺新增观察，不把新链接写回旧观察字段后破坏其摘要，也不把旧店铺标记为不存在。

## 复用核验命令

从项目根目录执行：

```powershell
python -m scripts.verify_seed_links
python -m scripts.verify_seed_links --sync-database
```

默认读取当前主名单和 `data/seed/shop_link_candidates.json`，同一天已核验的证据可以复用。根据市场、分组和身份映射追溯原始观察，不用新的 CSV 哈希覆盖旧哈希。候选文件包含近似名称和其他店铺，不能代替 verified CSV 使用。

核验命令输出证据与结果，不直接覆盖主 CSV。主名单和两个分流 CSV 本次由核验结果生成。若将更新后的主 CSV 作为新输入导入，链接、来源、日期和验证状态改变会产生新的观察哈希，这是新增观察，不是新增重复店铺。
