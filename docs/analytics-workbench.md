# 分析工作台、图片与持久匹配

工作台使用现有商品、规格、快照和事件建立可解释的分析维度。当前报价分布与服装结构使用最新已采集观察；顶部时间窗口只限定变化事件。未知字段保留为空，初次发现不当作平台上架，公开累计销量不用于推算日销量或成交额。

## 页面与分析口径

| 主题 | 主要内容 | 可执行动作 |
| --- | --- | --- |
| 店铺与价格 | 起价分布、店铺起价中位数、公开类目、价格评分散点、折扣、实际变化 | 点击价格带、店铺、类目或散点打开商品明细 |
| 服装结构 | 颜色、尺码、面料、风格、季节、品牌与颜色尺码矩阵 | 点击标签查询对应商品 |
| 库存与折扣 | 商品库存结构、当前 SKU 缺货率、折扣和规格热力图 | 点击库存或店铺下钻 |
| 竞品关系 | 已确认同款、精确 SKU 映射与当前可比价差 | 进入匹配页面核对与管理关系；本主题关系计数按全市场汇总 |
| 数据质量 | 字段与图片覆盖、详情新鲜度、真实历史跨度、实际事件 | 查看统计口径，明确缺数据的分析维度 |

图表设置控制模块显示，偏好保存在当前浏览器。卡片常驻标题、图表与必要数字，统计分母、覆盖范围及解释收进 ⓘ。多标签商品可进入多个分组。颜色与尺码保留原始体系，矩阵缺格表示未观察，不能判定缺货。矩阵最多展示 12 个颜色与 10 个尺码，ⓘ 提供实际 SKU 覆盖。散点最多 300 个商品，截断时保留紧凑的展示数/可用数标识。类目、店铺与属性排名为有限分组，未用截断样本冒充全部市场。

价格与评分图按当前实际评分范围调整横轴，价格轴使用整洁刻度。标记缩小并加白色描边；同评分的重叠点最多做 6 像素水平避让，价格坐标不偏移，精确评分与价格通过悬停查看。该视觉处理不修改源数据，点击仍打开对应商品。

聚合使用数据库中的完整筛选范围和精确中位数，不受旧版整份报告的 20,000 商品展示上限约束。商品明细通过服务端分页读取；默认导出当前页，勾选后可导出跨页已选商品。

商品分布与中位数在 SQL 中计算；当前 SKU 汇总按完整筛选范围，以 128 个商品的窄 ID 游标、独立 JSON 投影和每批 1,000 行 SKU 流式读取完成。当前 ID 按精确字符串集合匹配，重复 ID 不增计，数值、嵌套对象及其他币种不冒充当前 SKU。矩阵保留来源标签的大小写、重音及实际组合，仅去掉首尾普通空格。

工作台复用调用方事务，不创建临时表、不修改事务隔离、不隐式提交；默认 MySQL RR 下，同一次构建沿用同一读取快照。显式 RC 调用方保留自己的隔离语义。接口按查询范围合并并发相同请求，并缓存结果 30 秒，保留实际生成时间。

## 真实图片

`product_images` 保存商品 ID、原图、缩略图、顺序、公开来源、解析版本、观察时间与当前状态。同一商品图片以稳定业务哈希去重；详情图库优先于列表封面，旧图保留追溯。图片变化不改变商品价格、SKU 或原业务内容哈希。

列表与详情的新采集会写图片，历史已采数据不会凭空补出图片。可使用受限脚本 `python -m scripts.backfill_product_images --help` 选择最多 20 个商品补采。默认只显示计划，显式 `--execute` 才请求并写图库；请求仍经过已有 Redis 共享限速，限制响应按原规则暂停。图库 API 返回 `pending_schema`、`not_captured` 或 `available`，不会把统一服装图标当真实照片。

本地验证从真实公开详情取得并保存了商品 41 的 9 张图片，来源证据在 `data/samples/product-images/anrabess-20261014.json`。这是单个真实样本，不能代表全部商品图片覆盖；当前界面会显示实际覆盖率。

## 持久化匹配

`product_matches` 保存同款关系，`sku_matches` 保存双方具体规格映射。产品对规范排序并有唯一约束；SKU 必须属于各自商品，不能匹配商品自身或跨市场资源。候选仅是可解释的规则建议，当前最多扫描近期完成详情的 400 个商品、展示 20 条建议，界面提供扫描范围和评分依据。

人工确认同款后，可进一步选择双方当前 SKU。完整颜色、原始尺码和全部选项通过校验后才能保存映射。计算价差还要求当前币种、价格上下文与观察规格可比；数据漂移或资料缺失时明确显示不可比。撤销同款会同时撤销其 SKU 映射，重新确认同款不会自动恢复已撤销的 SKU；证据与备注保留。

写接口复用现有 Bearer Token 保护。前端只在会话内存保存用户输入的写入令牌，不放在 URL、本地存储或导出文件中。读图表和候选不需要写入令牌。

## 增量启用

历史 `001` 和 `002` SQL 保持不变，`003_product_images.sql` 与 `004_product_matching.sql` 是三张工作台扩展表的增量定义。商品介绍另用 `005_product_contents.sql`，本工作树的 `current_schema.sql` 包含十四张表。

```powershell
.\.venv\Scripts\python.exe -m scripts.migrate_workbench
.\.venv\Scripts\python.exe -m scripts.migrate_workbench --check
.\.venv\Scripts\python.exe -m scripts.migrate_workbench --execute
```

第一条完全离线，只打印计划和 SQL；`--check` 只读数据库元数据。`--execute` 只创建缺失的三张扩展表，原表缺失或结构漂移时拒绝继续，不 ALTER 原表、不改采集任务。本次仅在本机样本数据库执行，采集服务器未做发布、迁移或 Worker 重启。

生产发布使用独立版本标签。新 Worker 收到停止信号后停止领取任务，让当前任务完成提交与 ACK 再退出；旧进程仍按旧行为运行。启用图片与介绍补采前，必须核对全部 Worker 与 Scheduler 支持对应采集模式。发布与服务器入队由原部署任务统一执行。

## 实际验证

本地真实 MySQL 验证包含完整范围汇总、精确中位数、颜色尺码下钻、排序、图片首图与图库写入。新增表后的旧价格内容哈希、业务数据版本和详情时间保持原值。最终完整隔离 MySQL 回归为 321 passed、2 skipped；跳过项依赖独立 Redis 测试服务，未使用业务数据库执行测试。额外覆盖未知报价下钻，以及检测延迟时仍按真实观察时间和上海日期分组的边界。

浏览器验证包含真实样本的工作台、属性下钻、服务端商品列表和 9 图图库。持久匹配的完整浏览器链路在独立测试库执行：确认同款、刷新仍保留、确认 Red/S 规格的 10 / 12 USD 对照、得到 2 USD 价差、撤销父关系并保留映射历史，写入令牌不落浏览器存储。测试商品显式标记 `TEST FIXTURE`，没有向真实商品写入假匹配。截图与检查记录位于 `output/playwright/`。

DM Sans 与 Manrope 拉丁字体及其 OFL 许可证随前端本地提供，中文使用本机中文字体；页面不依赖外部字体服务完成呈现。
